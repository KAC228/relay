# Relay

Очередь обращений для небольшого производства. Демонстрационные данные — цех «Нордлайт», выдуманный заказчик.

Живой смысл проекта: показать, как устроен рабочий интерфейс, а не лендинг. Список, карточка, фильтры, которые живут в адресе страницы, и смена статуса без ожидания ответа сервера.

## Стек

React, TypeScript, Vite, TanStack Query, React Router, Vitest.

## Как запущено

Фильтры читаются из адреса: `/#/?status=open&priority=high&q=тираж&sort=priority`. Ссылку можно отправить коллеге, очередь откроется в том же срезе. Hash нужен, чтобы проект открывался с GitHub Pages без отдельного сервера.

Список грузится через TanStack Query. Смена статуса сначала меняет кэш, потом подтверждается запросом. Если запрос падает, очередь откатывается к прежнему списку.

Ответ клиенту уходит отдельной мутацией. Пока обращение было «новым», после ответа оно становится «в работе».

Клавиши, когда курсор не в поле ввода: `j` / `k` или стрелки двигают выделение, `1`–`4` ставят статус.

Логика фильтра и сортировки вынесена из компонентов и покрыта тестами. Сеть в демо — локальная функция с задержкой, чтобы были видны загрузка и оптимистичное обновление.


## Что говорить на собеседовании

- Фильтры лежат в URL, а не в случайном `useState`, поэтому состояние можно переслать и оно не теряется при обновлении страницы.
- Серверное состояние держит TanStack Query. Локально в стейте только выбранная строка и черновик ответа.
- Оптимистичное обновление: интерфейс не ждёт 300 мс, но при ошибке возвращает старые данные из контекста мутации.
- Тесты проверяют правила, а не вёрстку: статус, поиск по тексту, порядок по приоритету.
